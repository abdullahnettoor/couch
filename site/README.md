# Couch website (`site/`)

The landing page for [Couch](https://github.com/abdullahnettoor/couch), planned for `couch.abdullahnettoor.com`. A fully static site: plain HTML, CSS and TypeScript built with Vite into `dist/`, served by Cloudflare Workers static assets with no Worker script. No framework, no server code, no analytics, no cookies, no third-party requests (Geist and Geist Mono are self-hosted, SIL OFL); the only exception is the launch video's YouTube player, once there is a video and only after the visitor reaches YouTube on the first look's TV (its tile highlighted) (see "The first look's TV").

## Run it

The site lives in `site/` of the Couch app repo and is its own pnpm project (own `package.json`, lockfile and `pnpm-workspace.yaml`); the app's `vp check` and `vp test run` leave it out. Run everything from this folder:

```sh
cd site
pnpm install
pnpm dev          # http://localhost:5173
pnpm build        # type-check, then build to dist/
pnpm preview      # serve dist/ at http://localhost:4173
pnpm test         # CSS-scope fixtures, unit tests, and the browser tests (intro, page, the first look's TV)
pnpm launch:thumb # save the launch video's thumbnail (pnpm build runs it too; does nothing while LAUNCH_VIDEO.id is empty)
```

## Settings in one place

`src/config.ts` holds `GUMROAD_URL` (a **placeholder** until the Gumroad product exists), `GITHUB_URL`, `RELEASES_URL`, `DOWNLOAD_URL` (the "or download free from GitHub" links: always `https://github.com/abdullahnettoor/couch/releases/latest/download/Couch-arm64.dmg`, see "Publishing"), `WINDOWS_ISSUE_URL` and `SITE_URL`. They are filled into `index.html` at build time (`{{GUMROAD_URL}}` and so on), so every link works without JavaScript. `SOCIAL` (ticket 143) is the footer's list of social links, shown as icons only: the footer shows exactly the entries there (GitHub, X, LinkedIn and YouTube) and no list when it is empty. Each entry is `{ label, href, icon }`; `label` is the link's accessible name and tooltip, and `icon` picks a Phosphor brand mark from `SOCIAL_ICONS` in `vite.config.ts` (inline SVG, no requests; Phosphor is MIT, `public/licenses/`). An entry without an icon is shown as its label.

Section spacing (ticket 143) is four tokens in `src/style.css` `:root`, used by every section: `--section-pad` (section top and bottom), `--eyebrow-gap` (eyebrow → headline: 20px, 16px on phones), `--head-gap` (headline → body: 24px, 20px on phones) and `--intro-gap` (a centred heading → its content: 56px, 40px on phones).

## Screenshot slots

Every product picture is a **slot**, declared once in `src/slots.ts` (a typed manifest: slot name → interim file, alt text, width and height, `loading` priority). `vite.config.ts` reads it at build time and writes the `<img>` into `index.html` (`{{slot:name}}`), or into the place a mock stands in (`<!--mock:name-->…<!--/mock-->`). The build fails if `index.html` uses a slot the manifest lacks, or the manifest has a slot `index.html` never uses.

To replace a picture, drop a file named `src/shots/slot-<name>.png` (or `.jpg`, `.webp`) and rebuild. It wins over the manifest's `file` and over any CSS mock. The slot keeps its alt text, `width`/`height` and `loading` (`eager` for the first viewport, `lazy` for the rest) from the manifest, so edit those in `src/slots.ts` if the new picture differs (and write real alt text for what it shows). Crop shots so no UI is cut through: a Screen frame holding a picture takes the picture's own shape from its `width`/`height` (16:9 such as 1920×1080, or the Mac display's 16:10 such as 1920×1200; CSS mocks stay 16:9; setup steps are 16:9), about 9:19 for the Remote (1080×2280), each under about 150 KB. A dropped-in file has no `srcset`; the manifest's own pictures do (below).

## The wordmark (ticket 142)

COUCH as SVG paths, in the icon's orange with a soft vertical gradient (#ffc681 → #f28a3a → #c9601f). It replaced ticket 139's hand-drawn wordmark. **No font ships**: the site carries only the letters, as paths.

- **Where the letters live.** `src/brand/letters.ts` holds them in em units (cap height 100, baseline 0, the U centred on x = 0). To change the wordmark, edit that file, or redraw it from `src/brand/wordmark.svg` (the standalone copy) in a vector editor and copy the new paths back: C, C and H as path data; U and O as corner lists (below), so the intro can still morph them. Then `pnpm wordmark` rewrites `src/brand/wordmark.svg`.
- **No font files are committed.** `.gitignore` ignores `*.ttf` and `*.otf`, and a unit test fails if any font other than the Geist web fonts is tracked.
- **C, C and H** are plain SVG paths.
- **U and O** are rounded polygons, so they can morph: each corner is `[x, y, radius]`, with radius 0 for a square corner. The corners are in the logo's order (`src/brand/logo.ts`): the U has the sofa's eight (arm, arm, the cradle's two, arm, arm, the base's two), the O the Screen frame's four outside and four inside, so its slot becomes the Screen. The logo's corners are measured from `build/icon.png`, in the coordinates of the hero picture (`couch-glow.webp`, the icon's 832 × 688 crop), so the vector logo lands on the picture.
- **One size.** The letters' counters are wide open (the C's slot is 38% of the cap), so the nav uses the same outlines at 20 px tall; ticket 139's separate small optical size is gone.
- **Files.** `src/brand/wordmark.svg` is the standalone wordmark (`role="img"`, titled "Couch"), also used on the social card; `pnpm test` fails if it is out of date. The nav's copy is inlined at build time (`{{wordmark:nav}}` in `index.html`) inside the brand link, whose accessible name is "Couch, back to top". The Couch mark is the favicon (see "Other assets"); the square icon stays the app mark in Setup and Download, and the wordmark is the footer mark.

### The hero intro

On the first visit in a browser session, COUCH turns into the logo, then the hero copy arrives. Ticket 143 made it slower and cinematic (the user's review: "make it a little slow so we can feel it"): the logo is whole at about 3.2 s, and the copy starts arriving over the morph's last 0.6 s so the page is readable as the logo completes.

| Time | What happens |
| --- | --- |
| 0–0.76s | The five letters rise in, 40ms apart (0.6s each, Couch's `--ease`) |
| 0.76–1.25s | COUCH holds, still: a beat before anything moves |
| 1.25–2.25s | The C, C and H dissolve, outward from the U along a soft, noisy front (the H a little later); each bit leaves as a mote of warm dust |
| 1.25–2.9s | The dust drifts, slower and softer, into the Screen: about 220 small motes at 1440 px (about 120 on a phone), lifting and swaying like dust in a light beam before they gather |
| 1.35–2.6s | The O glides to the Screen's place on a gentle ease-in-out, dipping behind the U's arm; from 1.6s it becomes the frame, and from 1.9s it darkens to the frame's colour |
| 1.4–2.6s | The U widens into the sofa on the same gentle ease-in-out: its arms round into armrests, its base becomes the seat |
| 2.05–2.85s | The sofa's back rises behind the Screen |
| 2.3–3.35s | The Screen comes up like a slow exposure (no flicker) as the dust arrives, and its warm bloom swells a little past full and settles; the room's light comes up from 2.3s over 2s |
| 2.6–3.8s | The badge, "Settle in.", lead, buttons and meta arrive (opacity and a 14px rise, 0.9s each) |
| 2.8–3.55s | The icon's own glowing picture fades in over the vector logo, which fades out from 3s, so the existing hero mark (and its slow film flicker, from 3.8s) takes over in place |

**Two modes**, one constant: `INTRO_MODE` in `src/config.ts`, built in at build time (`COUCH_INTRO_MODE=logo-only` overrides it for one build).
- `"sequence"` (the default) is the table above: the logo first, then the words.
- `"logo-only"`: the badge, headline, lead, buttons and meta are there from the first paint (no 2.6s row); the morph plays only in the logo area and the glowing picture still fades in as the morph ends (2.8s). The head script adds `html.intro-logo`.

How it is built:
- **Before the first paint**, a small inline script in `<head>` (`introHead` in `src/brand/wordmark.ts`) decides whether to play. It plays only once per session (`sessionStorage`, `couch:intro`), never with `prefers-reduced-motion`, and never when the URL has a `#section`. If it plays, it adds `html.intro` (and `html.intro-logo` in the logo-only mode) and sets `--wm-s`, which sizes the wordmark to `min(720px, 88vw)` wide.
- **CSS keeps the timeline** (`style.css`, "Hero intro"): the letters' rise, the frame's colour, the back, the Screen, the glow, the picture and the copy, with transform and opacity only.
- **`src/intro.ts` does the rest on the same clock** (the CSS animation's start time on `document.timeline`; its `TIMES` match the CSS). The U and O are interpolated corner by corner and their rounded paths rebuilt each frame, so every in-between shape is clean; the O's position follows a shallow curve. The dust is a **small canvas** over the mark, added when the intro starts and removed when the dust has arrived (or the intro ends): the C, C and H are drawn into it once, each covered pixel gets a dissolve threshold (the letter, how far along it from the U, and value noise), worked out a few rows per frame while COUCH rises in so nothing stalls; each frame then clears what the front has passed and draws the motes as two soft pre-rendered sprites (additive). The dust is seeded, so every visit and every frame capture is the same. One `requestAnimationFrame` loop runs for about 2.9s. There is no library, only a small `cubic-bezier` solver. CSS `d: path()` interpolation is not used, because Safari does not animate `d`.
- **Skipping.** Any scroll, wheel, tap, click or key ends it at once: the copy and mark appear within 0.3s. So does a click or focus that comes without a pointer or key (assistive tech, `element.click()`, `focus()`), so no hero control is ever used while transparent; and a resize or rotation, because the wordmark was sized for the first viewport. Switching to reduced motion does the same. Coming back from the back/forward cache shows the end state at once, with no fade (`html.intro-now`). The intro's listeners and the dust canvas are removed when it ends.
- **Reduced motion** never starts the intro: the finished hero, no dust, no running animation.
- **Tests.** `scripts/intro.test.mjs` (part of `pnpm test`, needs Google Chrome) builds both modes, serves them and checks in headless Chrome that a pointerless click, a focus, a resize and a back/forward-cache return each end the intro with the copy, buttons and picture fully visible, the dust canvas gone and no intro listener left; that the dust canvas is there while the intro plays; that the ticket 143 timeline holds (COUCH still at 0.8–1.15s with no dissolve, the U widening and the dust out by 1.9s, no copy and no picture before 2.45s in sequence, the headline and the picture arriving at 3.05s while the morph is still on screen, the copy always visible in logo-only); and that reduced motion shows the finished hero with no dust and no running animation. `scripts/page.test.mjs` (also in `pnpm test`) builds once and checks the headline's loop (the order, about 3s each, back to "Settle in." and on to "Sit back." again; the line's four segments, the done ones full, the current one filling and the next empty, emptied as the loop restarts, centred in the gap under the h1, arriving with the headline; the h1's text and accessible name, an unchanged h1 box and no layout shift; the hover and focus pauses, with the line held still and going on with no jump; nothing, and no line, under reduced motion) and the Remote stage (the head and stage pinned together below the nav, steps 1–4 at 15/42/70/92% of the track and back again, the pacing (step 2 from 30%, 3 from 55%, 4 from 84%), the headline below the nav and the phone on screen at 1440 × 900 and 1024 × 768, unpinned with Replay at 1440 × 700, the track measured again after a layout change above it and no writes far from it, the rail filling and emptying, a step's button scrolling to its step, no wheel or touchmove listener, unpinned with Replay on a 390 px phone (waiting until the devices and the first step are in view) and under reduced motion, the Screen's share of the width and the phone in front of its corner). Since the ticket 143 review it also checks that a switch to reduced motion mid-loop or as the loop comes back to "Settle in." puts "Settle in." back at once (and hides the line, without moving the copy), that a resize to 320 px while "Lights down." shows fits it at once, and the font: whole-navigation CLS 0 under reduced motion at 1440 and 390 (the font's swap included; the headline test keeps its own CLS from the font being in), Geist preloaded from its built URL, and CLS < 0.001 with Geist held back 1.2 s.
- **No JavaScript.** If the module script never runs, the CSS timeline still ends on the finished hero; the C, C and H simply fade where they stand, and the U and O do not change shape.
- **Layout.** The hero's text and buttons are in the HTML from the start, and the intro only changes opacity and transforms (and draws in its own canvas), so nothing shifts (CLS 0). The intro SVG and canvas are `aria-hidden`.
- **Frames and video.** `node scripts/morph-frames.mjs <dir>` writes frames at fixed intro times (1440 and 390), the settled hero, a reduced-motion shot and `morph.webm` / `morph.mp4`, from `pnpm preview`. It slows the page clock with DevTools.

## The site's own motion (ticket 138)

Everything uses Couch's `--ease` and its durations (0.38s for moves and lifts, .12s and scale(.95) for presses, 0.7s for fades). Movement (lifts, presses, parallax, reveals, the sheen, the nav light, rolling digits, the cursor and card lights) is done with `transform` and `opacity` only, and no shadow ever animates: buttons and cards keep one static shadow and lift with a transform. The only other properties that change over time are paint-only: short colour and background fades on hover (≤ .25s). The hero light is blended once, not animated. (Couch's copied CSS keeps its own tile motion, `transform` and `box-shadow` on focus; see "Motion" above.) `prefers-reduced-motion: reduce` turns all of it off at any time (the hero intro never starts, or ends at once if the setting changes mid-way) (no transitions, no animations, no parallax, no pointer light, no hover lift or press scale on buttons, cards and step numbers; a digit already rolling is cancelled and shows its new value); the content and every end state are complete without it.

| Where | What | How |
| --- | --- | --- |
| Hero | The Screen in the Couch mark switches on (0.7s), the room's light comes up (1.6s), then a slow colour flicker plays on the Screen and in the room (12s loop, paused when the hero is off screen or the tab is hidden) | `.lamp-on`, `.lamp-film`, `.room-glow`; `main.ts` toggles `.playing` / `.paused` |
| Hero, first visit in a session (tickets 139 and 142) | COUCH dissolves into dust and morphs into the logo, then the copy arrives (about 2s, skippable; see "The hero intro"). It replaces the Screen's switch-on above; the room light and film follow the intro | `html.intro`, `.wm-intro`, `.wm-dust`, `src/intro.ts` |
| Hero | A soft light follows the pointer, eased each frame; on scroll the room's light moves slower than the page (parallax). The mark scrolls with the headline it lights, so the two never part or overlap | `[data-cursor-glow]`, `scrollScene()` |
| Badge | The dot sends out three rings, then rests; the arrow nudges on hover | `.pill .dot::after` |

## The first look's TV (ticket 145)

Under the hero, the TV pins (see "The site's own motion") and Couch's Home on it works as it does on a real Screen; opening YouTube plays the launch video, from YouTube. Built at build time by `src/launch-markup.ts` (with the live Home from `launchHome()` in `src/mocks.ts`), run by `src/launch.ts`, styled in `src/style.css` ("The first look's live TV").

**Home comes to life** over the screenshot, drawn in the same place, once the page's own pictures are in (idle after the load event and the intro, or when the TV starts to come into view; it waits at most 1.2s for the Continue tile's picture, `src/shots/launch-continue.webp`). The row is Couch's: YouTube, Netflix, Library, the divider, and Big Buck Bunny under Continue, highlighted as in the screenshot. The highlight is Couch's `.focused` (its .38s lift). Off the Continue tile, Home does what Couch does: the hero copy goes first under its own soft mask (.3s), the picture gives way to the wallpaper (.7s), then the clock and greeting come in; back on Continue, the picture returns.

**How it is used:**
- **Mouse:** pointing at a tile moves the highlight to it (only a real pointer move: a tile sliding under a still pointer as the page scrolls is not the visitor's doing); a click opens it.
- **Keys:** the TV is a group (`role="group"`, `aria-roledescription="TV"`, "Couch on the Screen"), and the row inside it a toolbar (`role="toolbar"`, "Couch Home", described by the hint) of real buttons, one per tile ("Open YouTube: <title>", "Open Netflix", "Open the Library", "Continue Big Buck Bunny (2008), 7 min left"), laid over Couch's own tile markup. It is one tab stop (a roving tabindex: Tab lands on the highlighted tile); ← → (and Home, End) move the highlight and the focus with it, only while the focus is in the TV, so elsewhere the arrows scroll the page as usual; Enter or Space opens. A click into the TV (off the tiles) puts the focus on the highlighted tile. Couch has no focus ring (the lift is its focus), so while the keys are in the TV its frame shows the site's focus colour.
- **Touch:** a tap opens the tile.
- **Phones: the Remote.** On the phone layout (`max-width: 700px` in portrait, or `max-aspect-ratio: 4/5`), a small Couch Remote sits under the TV and pins with it (`launchRemote()` in `src/launch-markup.ts`, `[data-remote]`): Couch's own D-pad (its `.pad`, `.dir` and `.ok` from `src/couch-ui/remote.css`, reset from the Remote page's full-screen frame) with only the keys that do something here, Left, Right and OK, and nothing else; a labelled group, "Remote", of real buttons ("Left", "Right", "OK"), with Couch's press (.12s, scale .95). ← → move the TV's highlight, OK opens the highlighted tile (YouTube: the player, cued) and does nothing in an opened App; going back is the Screen's "‹ Home" pill (at least 32px tall on phones; in the Library it stands over the screenshot's own "‹ Home", too small to tap there, in place of the invisible button the larger layouts use; on Netflix it sits under Netflix's bar, and the long caption pill is left out); a press counts as using the TV (the overlay goes, the scroll stops moving the highlight) and the focus stays on the Remote. Under it a caption says what OK does: "Big Buck Bunny · Tap OK to resume", "Your own films · Tap OK to open", "Netflix, with your own account · Tap OK", "YouTube · Tap OK to watch the launch video" (placeholder: "YouTube · Tap OK to open"), and in an opened App "Tap ‹ Home on the TV to go back". The caption is `aria-hidden` (it follows the scroll too); a visually hidden polite live region says the tile's name only when the Remote moves the highlight. The D-pad is sized to the room left under the TV (`--pad`: what the centred group leaves, at least 72px and at most 210px; 210px at 390 × 844, 360 × 740 and 375 × 667), 12px under the TV, so it fits 390 × 844, 360 × 740 and 375 × 667 without overflowing; the caption takes the whole width, so a new caption moves nothing (CLS 0). On the phone layout the hint pill goes (the caption says it) and the overlay's touch text becomes "Use the Remote below, or tap a tile". Reduced motion: no pin, the Remote still under the TV and working. Without script, and on wider windows: no Remote.
- **Skip.** While the TV is pinned (`[data-pinned]` on the track, set by `src/launch.ts` on the scroll frame it already runs), a quiet pill, "Skip ↓" (a button named "Skip the TV demo"), is part of the centred group: 16px under the TV, lined up with its right edge (phones: centred, 12px under the Remote's caption; its room is kept while it is hidden, so nothing moves), so it never covers the Screen or the Remote. It scrolls the next section (the Remote section) to the top under the nav, smoothly, and leaves the TV as it is (no use, no change). Hidden when the TV isn't pinned, without script, and under reduced motion (nothing pins).
- **The overlay.** Each time the TV comes into place (it pins; under reduced motion, it is 60% in view), until the visitor first uses it, a dark glass veil covers the whole Screen with how to use it, large: the ← → keys and a mouse, "Use the arrow keys or your mouse", "Enter or click opens a tile" (touch screens: a tap and "Tap a tile to open it"). It fades in (.35s), stays 2.5s (`VEIL_MS`), then fades out over Couch's .7s. Any use of the Screen takes it away at once and for good: a pointer moving over it (a real move), a tap or click, a key in the TV; so does the TV leaving its place (scrolling on past the pin, or back above it), and it comes back the next time the TV pins, in either direction, as long as the visitor hasn't used it. It takes no pointer and no scroll (`pointer-events: none`): the first click goes through to the tile under it. It is `aria-hidden` (the toolbar's description, the hint, says the same). Reduced motion: no fades. `data-veil` on `[data-launch]` is `on`, `fade` or absent.
- **The hint**, a small Couch pill over the Screen (hidden while the overlay is up): "Use ← → or your mouse. Press Enter to open." (touch screens, `(hover: none), (pointer: coarse)`: "Tap a tile."). It fades once the visitor first uses the TV (points at a tile, a key in it, a tap or click).

**The scroll, until the visitor uses the TV:** across the pin (160svh), the highlight moves for them in four even steps, Continue (0–25%) → Library (25–50%) → Netflix (50–75%) → YouTube (75–100%), and back when scrolling back. On YouTube the hint becomes "Press Enter or click to watch the launch video." (touch: "Tap YouTube to watch the launch video."). The scroll never opens anything, and once the visitor has used the TV it no longer moves the highlight. One rectangle read per scroll frame, only near the track.

**Opening** (Couch's own open): the Remote's key press on the lifted tile (.12s, scale .95, held .14s), then its face grows from the tile's box to the Screen (a `clip-path` inset, .9s) with its mark (or Big Buck Bunny's picture) riding from the tile's centre, then its view fades in (.5s) and a **Home** pill (‹ Home, "Back to Home") appears in the Screen's top right. Home or Esc goes back, with the highlight and the focus on the tile again. The views:
- **YouTube** → the launch video in YouTube's own player (below), or the placeholder poster.
- **Library** → a glimpse of Couch's Library (the Library section's screenshot, `library.webp`). Its own "‹ Home" (top left of the screenshot) is the view's Home: an invisible button laid exactly over it (named "Home", with the site's focus ring), and no Home pill, so there is one Home and the screenshot's clock stays clear.
- **Continue** → Couch's player on Big Buck Bunny with its controls (`src/shots/player.webp` and `-640`, 16:10, from the ticket 140 shoot's `player-controls.png`: `node scripts/shots.mjs <shootDir> player`).
- **Netflix** → Netflix's signed-in home inside Couch (`src/shots/netflix.webp`, `-1280`, `-640`, 16:10; see the screenshots notes), with the Home pill (moved just under Netflix's own top bar, by a `translate` so it is no layout shift) and Esc, and a caption pill at the bottom: "Netflix opens Netflix's own website, signed in with your account." (also the picture's alt text). Nothing is requested from Netflix: the picture is the site's own, and like the other views' it loads only once the TV is near.

**The launch video**, from `LAUNCH_VIDEO` in `src/config.ts`:
- **Placeholder** (`id: ""`): YouTube opens a Couch-made poster (the icon's light in a dark, warm room, with "Launch video" and "Coming soon to YouTube"), and the YouTube hint says "Press Enter or click to open YouTube." So a click or tap on the tile is a press on YouTube's own player: the video starts with sound and the play counts as a view, and the TV opens YouTube around it, the same iframe growing from the tile to the Screen as it plays (the press is seen as the focus moving into the iframe: the window's `blur`). Off YouTube the player stays loaded, hidden and out of the pointer's way, so passing over the tile again reloads nothing. Home removes the player (stopping the video), and a fresh cued one waits on the still highlighted tile. Inside YouTube's player the keys are YouTube's, so Esc works from the Home pill or the TV (Shift+Tab from the player reaches Home). The privacy fact "No Couch analytics" becomes "Couch adds no analytics or cookies. YouTube loads only when you reach YouTube on the TV above, and may use cookies or browser storage under Google's privacy policy." and the footer's line "No cookies or analytics from Couch." (in placeholder mode both keep their old wording).

No layout shift: everything is inside the TV's box, and nothing is under it. **Reduced motion:** no pin, no growth and no scroll-driven highlight; the TV works the same by mouse, keys and touch, with no transitions and no opening clip (a view opens at once); a switch to reduced motion takes effect at once. **Without script:** the Home screenshot (the live Home is `hidden` and `inert` in the HTML until the script brings it to life).

## Deploy

`wrangler.jsonc` serves `dist/` with Workers static assets on the custom domain `couch.abdullahnettoor.com`: `assets.directory` and `not_found_handling: "404-page"` (`public/404.html`), and nothing else. There is no `main`, so no Worker script runs: every request is a file from `dist/` or the 404 page ([Cloudflare: Static Assets](https://developers.cloudflare.com/workers/static-assets/)). `pnpm deploy` builds and runs `wrangler deploy`, which creates the subdomain and its certificate. 

Two ways to deploy, both from `site/`:

- **From this Mac:** `cd site && pnpm deploy` (needs `wrangler login` with the account that owns the `abdullahnettoor.com` zone).
- **From GitHub (Workers Builds),** if the repo is connected in the Cloudflare dashboard (Workers & Pages → the `couch-site` Worker → Settings → Build):

  | Setting | Value |
  | --- | --- |
  | Root directory | `site` |
  | Build command | `pnpm install --frozen-lockfile && pnpm build` |
  | Deploy command | `npx wrangler deploy` |
  | Output | `dist/` (set by `assets.directory` in `wrangler.jsonc`; not a separate setting) |
  | Production branch | `main` |
  | Non-production branches | Builds on, so other branches (`dev` among them) get preview URLs |
  | Build watch paths | `site/**` (so app-only commits don't rebuild the site) |

  `pnpm build` also runs `tsc` and `scripts/launch-thumb.mjs` (which fetches nothing while `LAUNCH_VIDEO.id` is empty, and uses the committed thumbnail once it isn't). 

**Live since 6 November 2026** at https://couch.abdullahnettoor.com, first deployed from the maintainer's Mac with `pnpm deploy` (Worker `couch-site`). The Worker's workers.dev address is off (`workers_dev` is not set, so `wrangler deploy` disables it); `preview_urls` is **off** (12 Nov 2026), which takes every old version's preview URL offline, since Cloudflare can't delete single versions. Turning it on brings them all back, and Workers Builds' branch previews need it on. Until it's connected, deploy from the Mac after merging a site change into `main`.

## Publishing

`main` is the live site: Workers Builds deploys it on every push that touches `site/**`. `dev` acts as staging: its builds get a preview URL, not the live domain.

- **Site-only changes** (copy, design, fixes that don't wait on the app): branch from `main`, merge into `main`, then merge `main` into `dev` so `dev` keeps them.
- **Site changes tied to an unreleased app feature** go through `dev` like app work, and reach the live site with the stable release (the `dev` → `main` merge).
- **The download link** ("or download free from GitHub", `DOWNLOAD_URL`) always points at `https://github.com/abdullahnettoor/couch/releases/latest/download/Couch-arm64.dmg`. The release assets keep that file name with no version in it, so the link always gets the newest stable release and never needs changing for a release.
